## 프로젝트 구조

DDD(Domain-Driven Design) 패턴을 기반으로 도메인별 패키지를 구성합니다.

```
src/main/java/com/newbranch/backend/
├── domain/               # 도메인별 패키지
│   ├── attachment/       # 첨부파일 (controller / dto / entity / repository / service)
│   ├── code/             # 공통 코드 (entity / repository)
│   ├── consolidation/    # 정리(요약) 도메인
│   ├── goal/             # 학습 목표
│   ├── mylearning/       # 나의 학습
│   └── user/             # 사용자
├── global/
│   ├── common/           # 공통 응답 구조 (entity / response)
│   ├── config/           # 전역 설정 (CORS, Swagger 등)
│   ├── error/            # 예외 처리
│   └── security/         # 인증/인가
│       ├── jwt/
│       └── oauth2/       # OAuth2 로그인
└── infra/                # 외부 연동
    ├── extraction/       # 텍스트 추출
    ├── openai/           # OpenAI 연동
    └── s3/                # 파일 스토리지(S3)
```

각 도메인 패키지는 아래 레이어로 구성됩니다.

- `controller/` — REST API Controller
- `service/` — 비즈니스 로직
- `repository/` — 데이터 접근 계층
- `entity/` — JPA Entity
- `dto/` — 요청/응답 DTO

## 인증/보안 구조

- `global/security/jwt` — JWT 발급/검증
- `global/security/oauth2` — OAuth2 소셜 로그인
  (`CustomOAuth2UserService`, `OAuth2SuccessHandler`,
  `HttpCookieOAuth2AuthorizationRequestRepository` 등)
- `CustomUserDetailsService`, `JwtAuthenticationEntryPoint`,
  `JwtAccessDeniedHandler`로 인증/인가 예외를 처리합니다.

## 개발 워크플로우

### 1. 로컬 개발 환경 설정

1. Docker & Docker Compose 설치
2. `.env` 파일 생성 (`.env.example` 복사)
3. PostgreSQL 컨테이너 실행
4. 애플리케이션 실행 및 연결 확인

### 2. 이슈 & 브랜치 전략

- GitHub Issues에서 템플릿(🐞 Bug report / 🛠️ Feature report / ❓ Question)을
  선택해 이슈 생성
- 브랜치 네이밍: `feature/기능명`, `fix/버그명`

### 3. 커밋 컨벤션

| 접두어 | 의미 |
| --- | --- |
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 |
| `refactor` | 리팩토링 |
| `test` | 테스트 추가 |
| `chore` | 기타 변경사항 |

### 4. PR & 코드 리뷰

1. 브랜치 푸시 후 Pull Request 생성
2. GitHub Actions가 자동으로 빌드 검증 (CI)
3. 팀원 리뷰 완료 후 `main` 브랜치로 병합

## CI/CD 파이프라인

**CI — PR 빌드 검증**

- 트리거: Pull Request 생성/업데이트 시
- Java 17 설정 → `./gradlew clean build -x test` → 빌드 성공/실패를 PR에 표시
- 목적: `main` 병합 전 빌드 오류 사전 차단

**CD — Docker 이미지 배포**

- 트리거: `main` 브랜치에 push 될 때
- Gradle 빌드 → Docker 이미지 빌드 → Docker Hub 푸시
  - `latest`: 최신 버전
  - `main-<커밋해시>`: 특정 커밋 버전 (롤백용)
  - `main`: 브랜치 태그
- 목적: 배포 가능한 Docker 이미지 자동 생성

> 워크플로우 실행 내역은 GitHub 레포지토리 Actions 탭에서 확인할 수 있습니다.
